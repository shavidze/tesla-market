# TeslaMarket დიზაინის ფილოსოფია — „ნაკლები, მაგრამ უკეთესი"

საფუძველი: **Dieter Rams, „Weniger, aber besser"** (Braun, 1960-80-იანები) — 10 პრინციპი,
რომელმაც Apple-ისა და Tesla-ს დიზაინ-ენა შვა. დამატებითი ფენა: **Bernard Arnault-ის (LVMH)
merchandising პრინციპები** — პროდუქტი გმირია და ყოველი touchpoint მოწმდება.

ეს დოკუმენტი ნორმატიულია: ყველა UI გადაწყვეტილება აქ მოწმდება. ცვლილება — ჯერ აქ, მერე კოდში.

## Rams-ის 10 პრინციპი — TeslaMarket-ზე გადათარგმნილი

| # | პრინციპი | ჩვენთან ნიშნავს |
|---|----------|-----------------|
| 1 | ინოვაციური | ინოვაცია მხოლოდ იქ, სადაც ნაწილის პოვნას/ყიდვას აჩქარებს (მაგ. OEM ძიება, AI აღწერა). ტრენდის დევნა — არა. |
| 2 | სასარგებლო | ყველა ელემენტი ერთ კითხვას ემსახურება: „იპოვის და იყიდის თუ არა მყიდველი ნაწილს?" თუ არა — იშლება. |
| 3 | ესთეტიკური | სილამაზე პროპორციიდან, თეთრი სივრციდან და ფოტოს ხარისხიდან მოდის — არა დეკორაციიდან. |
| 4 | გასაგები | მყიდველი ტელეფონიდან 5 წამში ხვდება: რა ნაწილია · მოერგება თუ არა მის მანქანას · რა ღირს · როგორ მიიღოს. ინსტრუქცია არ სჭირდება. |
| 5 | პატიოსანი | რეალური ფოტოები. მდგომარეობა (ახალი/მეორადი) ყოველთვის ჩანს. არა ყალბი ფასდაკლებები, ტაიმერები, „ბოლო ცალია" თეატრი. |
| 6 | თავშეკავებული | UI ინსტრუმენტია, არა ექსპონატი. წითელი მხოლოდ ფასზე + დარეკვის CTA-ზე — ერთ ეკრანზე ერთხელ. |
| 7 | ხანგრძლივი | არა სეზონური ტრენდები. სისტემა 5 წელიწადში ისეთივე კარგი უნდა იყოს. Tokens ცვლილება = ფილოსოფიის ცვლილება. |
| 8 | თანმიმდევრული ბოლო დეტალამდე | ერთი spacing scale, ერთი radius (`rounded-card`), `min-h-11` tap targets, `formatPrice` ყველგან. ერთი შეუსაბამო დეტალი ნდობას შლის. |
| 9 | ეკოლოგიური | ციფრულად: მსუბუქი გვერდები, მინიმალური JS, ცოტა request. სისწრაფე = პატივისცემა (და free tier-იც). |
| 10 | რაც შეიძლება ნაკლები დიზაინი | ყველა ახალ UI იდეაზე default პასუხი: **არა**. ემატება მხოლოდ ის, რისი საჭიროებაც დამტკიცდა. |

## Arnault-ის ფენა — merchandising

1. **პროდუქტი გმირია.** ფოტო ნეიტრალურ ფონზე, დიდი, სუფთა. თეთრი სივრცე ფოტოს გარშემო = აღქმული ღირებულება. UI არასდროს ეჯიბრება პროდუქტს.
2. **ყოველი touchpoint მოწმდება.** Arnault შაბათობით მაღაზიებს ივლიდა — ჩვენთან ამას hooks აკეთებს: დიზაინის ყოველი ცვლილება გადის gate-ს (ქვემოთ).
3. **ხარისხის ფანატიზმი.** დეტალი, რომელსაც „მაინც ვერავინ შეამჩნევს" — ზუსტად ის დეტალია, რომელიც მოწმდება.

## მყარი წესები (არ ირღვევა)

- **Tokens only:** `bg` #FAFAFA · `ink` #171717 · `ink-muted` #737373 · `accent` #E10600 · `line` #E5E5E5 · `rounded-card` 8px · Noto Sans Georgian (400/500/700). Raw hex კომპონენტში = blocker.
- **Accent დისციპლინა:** წითელი მხოლოდ ფასი + დარეკვის CTA. მესამე წითელი ელემენტი ეკრანზე არ არსებობს.
- **Borders, არა shadows.** სიბრტყე და სიცხადე.
- **Mobile-first:** მყიდველი ტელეფონზეა. Tap targets ≥44px (`min-h-11`), `tel:` ლინკები მუშა.
- **ქართული ტექსტი:** ბუნებრივი, გრამატიკულად სწორი, ტერმინოლოგია ერთიანი (მეორადი, არა „used").
- **ფასის ფორმატი:** `1 234 ₾` (space grouping, `formatPrice`-ით).

## Gate — როდის და როგორ მოწმდება

1. **დაწყებისას:** UI/დიზაინის იმპლემენტაციამდე იკითხება ეს დოკუმენტი (`design-philosophy` skill).
   სამი კითხვა კოდამდე: (ა) რომელი პრინციპი ამართლებს ამ ელემენტს? (ბ) რისი წაშლა შეიძლება
   დამატების ნაცვლად? (გ) პროდუქტი რჩება თუ არა გმირად?
2. **დასრულებისას:** `design-guardian` agent აუდიტს ატარებს ამ დოკუმენტის მიხედვით.
   Blocker findings ისწორება commit-ამდე.
3. **ავტომატიკა:** `.claude/hooks/design-gate.mjs` (PostToolUse) UI ფაილის პირველ ცვლილებაზე
   ახსენებს gate-ს; Stop hook კი აფრთხილებს, თუ სესია სრულდება დაუდიტებელი UI ცვლილებებით.
