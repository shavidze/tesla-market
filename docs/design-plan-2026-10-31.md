### C1 — „დარეკვა" ყოველთვის ხელთ (პროდუქტის გვერდი, მობილური)

**Frame:** როცა მყიდველი ტელეფონით პროდუქტის გვერდს ხსნის (ხშირად ავარიის შემდეგ, სახელოსნოში), მას სურს ერთი შეხებით დარეკოს, რომ თავსებადობა და მარაგი დაადასტუროს, გადახვევისა და ღილაკის ძებნის გარეშე.

**რეფერენსი:** სტიკი CTA მობილურ პროდუქტის გვერდზე — გავრცელებული პატერნი ([GoodUI #41 — Sticky Call To Action](https://goodui.org/patterns/41)); ქართულ განცხადებების საიტებზეც (myauto.ge, ss.ge) „დარეკვა" მობილურზე ქვედა ზოლშია (ჩემი დაკვირვება, ამ სესიაში არ გადამიმოწმებია → *unconfirmed*).

**რეკომენდაცია:** არსებული „დარეკვა" ღილაკი იქცევა `position: sticky; bottom: 0` — **ახალი ელემენტი არ ემატება**. სანამ ღილაკის ბუნებრივი ადგილი ეკრანის ქვემოთაა, ის ეკრანის ძირზე „ეკვრის"; როცა მომხმარებელი მის ადგილამდე ჩავა, ჩვეულებრივად დგება ფასის ქვეშ; აღწერის შემდეგ სვეტთან ერთად მიდის. Desktop უცვლელია.

უარყოფილი ვარიანტები:
- *ცალკე fixed ქვედა ზოლი (ფასი + დარეკვა)* — მეორე წითელი ელემენტი ეკრანზე (accent დისციპლინა) და ფასის დუბლირება.
- *ფოტოს შემცირება / სათაურის `text-2xl`* — გაზომვით ~150px-ს იგებს, ღილაკი მაინც 844px-ის ქვემოთ რჩება; ამასთან პროდუქტი-გმირს ასუსტებს.

**ქცევა:**
1. მობილური (<768px): CTA-ს wrapper `sticky bottom-0`, თეთრი ფონი, ზედა საზღვარი `border-line` — კონტენტი მის ქვეშ გადის.
2. Sticky-ს საზღვარი = მარჯვენა სვეტის `div` (`md:col-span-2`): ფოტოს ზონაში და სვეტის დასრულების შემდეგ (ფუტერზე) ღილაკი აღარ ეკვრის.
3. ≥768px: `md:static`, ყველა დამატებითი სტილი ნულდება — დღევანდელი იერი.

**დამატებით ამავე ფაილში (ორი პატარა გასწორება):**
- მიღების ხაზი (F8): `მიღება: მაღაზიაში, {address}` → **`მიღება მაღაზიაში: {address} · {hours}`** (მაგ. „მიღება მაღაზიაში: რუსთავი · ორშ–შაბ, 10:00–19:00"). საათები settings-იდან მოდის; რეალური მნიშვნელობა მფლობელმა უნდა გადაამოწმოს (*unconfirmed*).
- „აღწერა" სექცია არ ჩანს, თუ `descriptionKa.trim() === titleKa.trim()` (F9) — იგივე ინფორმაციის მეორედ ჩვენება ხმაურია.

**Microcopy:** ღილაკი უცვლელად — „დარეკვა". ახალი სტრიქონი მხოლოდ მიღების ხაზია (ზემოთ).

### C2 — ბარათზე სათაური 3 ხაზამდე + წლების ერთიანი ფორმატი

**Frame:** როცა მყიდველი კატალოგს ტელეფონზე ათვალიერებს, მას სურს ბარათიდანვე გაარჩიოს მსგავსი ნაწილები (მარჯვენა/მარცხენა, წინა/უკანა), რომ არასწორი არ გახსნას და არ დარეკოს არასწორზე.

**რეკომენდაცია:** `line-clamp-2` → `line-clamp-3`. მობილურზე ~20 სიმბოლო ხაზზე → 3 ხაზი ფარავს ~60 სიმბოლოს; ამჟამინდელი სათაურების უმრავლესობა სრულად ჩანს.

უარყოფილი:

### C3 — კატალოგი: „მანქანის წელი" ფილტრი

**Frame:** როცა მყიდველი თავისი მანქანისთვის ნაწილს ეძებს, მას სურს მოდელთან ერთად წელიც მიუთითოს, რომ სიაში მხოლოდ ის ნაწილები დარჩეს, რომლებიც შეიძლება მოერგოს — და არა 26 ბარათი, რომელთა მეტა-ხაზი სათითაოდ უნდა წაიკითხოს.

**რეფერენსი:** ავტონაწილების მაღაზიების ძირითადი პატერნი — Year/Make/Model ფილტრი ([Inchoo — Will it fit? Must-have features for automotive eCommerce](https://inchoo.net/?p=4147); [Baymard — automotive parts benchmark](https://baymard.com/ux-benchmark/collections/automotive-parts)). ჩვენთან make ყოველთვის Tesla-ა, მოდელი უკვე არის → აკლია მხოლოდ წელი.

**რეკომენდაცია:** ერთი `<select>` „ფილტრები"-ს შიგნით, მოდელის შემდეგ. დამალულია იმავე `details`-ში — მუდმივად ხილული ელემენტი არ ემატება (Hick).

უარყოფილი:
- *„ჩემი მანქანა" ცალკე ბლოკი კატალოგის თავში (მოდელი + წელი, დამახსოვრებით)* — ახალი ხილული ელემენტი + cookie/localStorage მდგომარეობა; v1-ისთვის ზედმეტი.
- *წლის ველი მთავარ გვერდზე მოდელის ფილებთან* — მეორე შესასვლელი იმავე ფილტრისთვის; ჯერ კატალოგში დავამტკიცოთ.

**ქცევა:**
1. ოფციები: `ყველა წელი` (value `""`), შემდეგ წლები **მიმდინარე წელი + 1 → 2012** კლებადობით (loader ითვლის, client არა — hydration mismatch-ის თავიდან ასაცილებლად). დიაპაზონი მხოლოდ UI-ს საზღვარია, თავსებადობის მტკიცება არ არის.
2. URL: `?year=2021`. არავალიდური/დიაპაზონს გარეთ → იგნორირდება (როგორც დღეს `model`).
3. ფილტრის ლოგიკა: ნაწილი ჩანს, თუ `(year_from IS NULL OR year_from ≤ Y) AND (year_to IS NULL OR year_to ≥ Y)`. **წლების გარეშე ნაწილები (მაგ. უნივერსალური) რჩება სიაში** — უცნობი ≠ „არ ერგება" (ღია კითხვა Q1, default = რჩება). ბარათზე წლები მაშინ უბრალოდ არ ჩანს — პატიოსანია.
4. `activeFilterCount` ითვლის წელსაც → „ფილტრები (2)".
5. აქტიური ფილტრების ხაზი: `Model 3 · წელი: 2021 · ძარა · …` + „გასუფთავება".
6. `meta` noindex წესში ემატება `year`.

**Microcopy:**
- `aria-label`: „მანქანის წელი"
- ცარიელი ოფცია: „ყველა წელი" (დოკუმენტირებული „ყველა …" პატერნი)

### C5 — Admin: უკუკავშირი და შეცდომის პრევენცია (კოდზე დაყრდნობით)

**Frame:** როცა მფლობელი საწყობში ტელეფონით ნაწილს ამატებს ან ასწორებს, მას სურს ზუსტად იცოდეს, შეინახა თუ არა, აიტვირთა თუ არა ფოტო და რომ შემთხვევითი შეხება ფოტოს არ წაშლის — რომ არაფერი გაიმეოროს და არაფერი დაკარგოს.

**რეკომენდაცია:**
1. **შენახვის შეტყობინება (PRG-ის შენარჩუნებით):** edit action redirect → `/admin/products/{id}/edit?saved=1`; new action → `/admin/products/{id}/edit?created=1`. Edit loader კითხულობს პარამეტრს და გადასცემს `notice`-ს. შეტყობინება ჩანს ფორმის თავში მხოლოდ მაშინ, როცა `actionData` არ არის (რომ ფოტოს ატვირთვის შემდეგ ძველი „შენახულია" არ დარჩეს).
2. **ფოტოს შედეგი:** ატვირთვის/წაშლის შემდეგ ფოტოების სექციაში `role="status"` შეტყობინება.

4. **წაშლის დადასტურება:** `window.confirm` ფოტოს წაშლის `Form`-ის `onSubmit`-ზე.

- *წაშლის „ორჯერ შეხებით" დადასტურება (state-ით)* — ერთ ფოტოზე მეტი state და ტექსტის ცვლა; native confirm admin-ში საკმარისია და OS-ის ლოკალიზებულ ღილაკებს აჩვენებს. (Style guide-ის „popup-ების აკრძალვა" store-ის მარკეტინგულ popup-ებს ეხება.)

- **რისკი (code-reviewer, upload):** (1) თანმიმდევრულობა სავალდებულოა (`sortOrder` race); (2) R2 `put` შეცდომა შუა ციკლში — უკვე ატვირთული რჩება, დანარჩენზე 500; მისაღებია v1-ში, მაგრამ შეამოწმოს, რომ DB-ში ობოლი ჩანაწერი არ რჩება (`addPhoto` ჯერ R2, მერე DB — ობოლი შეიძლება იყოს R2-ში, არა DB-ში); (3) Workers request body ლიმიტი; (4) ფაილის სახელი შეცდომის ტექსტში — React escape-ს აკეთებს, `dangerouslySetInnerHTML` არ გამოიყენო; (5) MIME შემოწმება სერვერზე უცვლელია.

## 6. რაც არ უნდა შეიცვალოს (მუშაობს)

- **ბარათის მეტა-ხაზი სათაურზე მაღლა** (`MODEL · წლები · მდგომარეობა`) — მყიდველი ჯერ „მოერგება?"-ს ამოწმებს. C2 მხოლოდ სათაურის ხაზებს ცვლის.
- **პროდუქტის გვერდზე სპეცები (მოდელი, წლები, მდგომარეობა, OEM) ფასამდე** და „ნაწილის კოდი" + მინიშნება „მიუთითე ნაწილის კოდი ან OEM ნომერი" — ზარს მოკლეს და ზუსტს ხდის.
- **Accent დისციპლინა** — ყველა შემოწმებულ ეკრანზე წითელია მხოლოდ ფასი და „დარეკვა". C4 ამას ინარჩუნებს.
- **ფოტოები `object-contain` ნეიტრალურ ფონზე** — არაფერი იჭრება; პროდუქტი გმირია.
- **ცარიელი შედეგის აღდგენის გზა** (აქტიური ფილტრების ხაზი + „გასუფთავება") და მობილურზე ყოველთვის ხილული ძებნა.
- **მოდელის ფილები რაოდენობით** მთავარზე — ყველაზე სწრაფი შესასვლელი.
- **Admin-ის მობილური ბარათები, „შესავსებია: …" მინიშნებები და სტატუსის შენახვის უკუკავშირი** — C5 სწორედ ამ პატერნს ავრცელებს რედაქტირების გვერდზე.

## 7. ვალიდაცია — ერთი პატარა ადამიანური ტესტი

**5 ადამიანი** (Tesla-ს მფლობელი ან ხელოსანი), საკუთარი ტელეფონით, production-ზე:
> „შენი 2021 წლის Model 3-ისთვის იპოვე უკანა ბამპერის **მარჯვენა** რეფლექტორი და დარეკე მაღაზიაში."

ვითვლით: შეხებების რაოდენობას პირველ ეკრანიდან ზარამდე · დროს · შეცდომებს (არასწორი მხარის გახსნა, „ვერ ვიპოვე ღილაკი", ფილტრის გამოტოვება). ზარი შეიძლება ბოლო ეკრანზე შეწყდეს.
**წარმატება:** 5-დან ≥4 ასრულებს არასწორი მხარის გახსნის გარეშე და პროდუქტის გვერდზე „დარეკვას" გადახვევის გარეშე აჭერს.

**Admin:** Saba თავად — ტელეფონით, საწყობში: ახალი ნაწილი 4 ფოტოთი. ვზომავთ დროს „+ დამატება"-დან ბოლო ფოტომდე და რამდენჯერ დასჭირდა გამეორება/გადამოწმება.
